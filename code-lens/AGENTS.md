# Copilot instructions for code-lens

## Build and test

- Bootstrap vendored dependencies with `scripts/vendor-deps.sh` when `vendor/sqlite`, `vendor/tree-sitter`, `vendor/tree-sitter-clojure`, `vendor/tree-sitter-java`, `vendor/tree-sitter-c`, `vendor/tree-sitter-python`, `vendor/libdeflate`, or `vendor/zlib` are missing. On native Windows use `scripts\vendor-deps.bat`. SQLite is a pinned amalgamation archive verified by SHA-256; the tree-sitter and libdeflate dependencies are pinned git clones.
- Build the release CLI with `make`, `make all`, or `make release`; the binary is copied to `build/code-lens`. On native Windows, `build.bat release` and `build.bat debug` use the Clang on `PATH` and produce `build\code-lens.exe`; `build.bat clean` cleans it. Release objects live under `build/release/` and use `-O3 -DNDEBUG -march=native -flto` by default.
- Build a debug CLI with `make debug`; debug objects live under `build/debug/`, use `-O0 -g` with no LTO by default, and are also copied to `build/code-lens`.
- Run the full test suite with `make test` for the current/default release mode, `make test-release`, or `make test-debug`. The active test binary is copied to `build/tests/test-main`; there is no test filter or per-test target, so focused test work usually means adding/narrowing assertions in `tests/test_clojure_parser.c`, `tests/test_java_support.c`, `tests/test_c_support.c`, `tests/test_python_support.c`, or `tests/test_main.c` and running the relevant test target. Test objects declare `include/code_lens.h` as a prerequisite; without that, a public-struct layout change silently linked stale test objects against fresh app objects and segfaulted (fixed 2026-07, keep the header in the pattern rule).
- Run `make check-c23` if compiler standard detection is relevant.
- Use `make clean && make release` before performance comparisons after changing build flags, LTO flags, or SQLite compile defines.
- The Makefile removes `build/code-lens` and `build/tests/test-main` before copying fresh builds over them; keep that `rm`-then-`cp` shape, because overwriting a previously executed binary in place makes the macOS kernel kill subsequent executions over a stale code-signature cache.
- Run indexing benchmarks with `scripts/benchmark-index.sh --path <repo-path> --expect-files <n> --expect-symbols <n> --expect-references <n> --expect-keywords <n> --expect-aliases <n>`. The script creates isolated `CODE_LENS_HOME` directories, runs warmups/measured iterations, validates counts, verifies (outside the timed window) that the produced index surfaces the same per-table row counts through `sql` read-back, and reports median/mean/min/max.
- For CPU profiling with symbols, avoid LTO+debug builds because they can compile very slowly. Prefer `make release OPTFLAGS='-O3 -g -DNDEBUG -march=native' LTOFLAGS=` and run short index jobs with `CODE_LENS_INDEX_THREADS=1` so `sample` has enough time to collect useful stacks. For very short jobs, rely on `scripts/benchmark-index.sh` exact counts and median timings rather than a sparse `sample` report.

## Architecture

- This is a pure-C native ISO C23 project; project-owned sources are compiled with `-Wall -Wextra -Wpedantic -Werror -pedantic-errors` and the final binary links with the C compiler (no C++ anywhere).
- `src/code_lens.c` contains all project-owned application implementation. Keep it organized by sections: arena allocator, language registry, platform helpers, string builder, dependency adapters, database wrapper, Clojure parser, tree-sitter helpers, Java parser, C parser, Python parser, indexer, search/query helpers, MCP server, CLI dispatcher, and `main`.
- `include/code_lens.h` is the single public header. Tests compile `src/code_lens.c` again with `CODE_LENS_NO_MAIN` so `tests/test_main.c` remains the test entry point.
- The CLI command dispatcher handles `index`, `remove`, `list`, `query`, `context`, `sql`, and `mcp`.
- Platform helpers own filesystem utilities, recursive supported-source walking (`.clj`, `.cljc`, `.cljs`, `.bb`, `.java`, `.c`, `.h`, and `.py`), language-specific compatibility walkers, skipped directories, and `CODE_LENS_HOME` defaulting to `~/.code-lens`.
- The language registry (`languages[]`, one `LanguageSpec` per language: name, grammar, extensions, dependency-JAR flag, tree-sitter language, parser new/delete/parse adapters, optional `forces_full_rebuild(path)` hook) drives extension routing (`language_for_path`), per-worker parser construction and dispatch (unregistered extensions parse as Clojure), dependency-JAR entry filtering, incremental full-rebuild triggers, `version --deps`, and the public `code_lens_language_count`/`code_lens_language_info`. Adding a language = pin `tree-sitter-<name>` in `vendor/deps.lock`, append it to `GRAMMARS` in the `Makefile` and `build.bat` (each compiles `src/parser.c` plus `src/scanner.c` when present), write its parser section, and add one registry entry (see developer.md section 9).
- The Clojure parser extracts namespaces, require aliases, definitions, symbol references, and keyword usages. The default backend is a hand-written reader (`cp_*` functions in `src/code_lens.c`) that matches tree-sitter-clojure behavior exactly; any file it does not model with certainty falls back to tree-sitter (counted by `code_lens_clojure_reader_fallbacks()`, printed as `reader_fallbacks` under `CODE_LENS_PROFILE=1`). `CODE_LENS_PARSER=treesitter` forces the tree-sitter backend everywhere. Parser-behavior changes must keep `tests/test_clojure_parser.c` green under both backends, including the differential test.
- The Java parser uses tree-sitter-java. It extracts packages, normal and static imports, type/member definitions, enum constants, Javadocs, type references, field accesses, method references, and calls. Java symbols use their fully qualified enclosing type as `namespace`; normal imports become `Alias` rows and static imports become `Referred` rows. Receiver resolution is syntax-driven (imports, enclosing/super types, and declared field/local/parameter types), not compiler attribution. Keep `tests/test_java_support.c` green when changing it.
- `context` automatically renders an exact Java type target as a bounded Class Dossier rather than generic definition/reference tables. It selects declared members, hierarchy and overrides, behaviorally relevant inherited methods/supporting types, and representative usages grouped by purpose; preserve its `CLASS_DOSSIER_*` bounds and avoid dumping unrelated inherited APIs.
- Dependency projects are detected in root-file priority order: `pom.xml`, then `project.clj`, then `deps.edn`, then a root Python virtualenv (`.venv/pyvenv.cfg` or `venv/pyvenv.cfg`). Maven uses `mvnw`/`mvn` and the pinned Maven Dependency Plugin (`copy-dependencies` with the `sources` classifier, then a best-effort `list` whose main JARs embedding sources and lacking a sibling `-sources.jar` are materialized, which is how Clojure libraries are indexed); Leiningen uses `lein classpath`; tools.deps uses `clojure -Spath` plus an optional `-M:alias` basis. Maven inputs (`pom.xml`, local parents, wrappers, `.mvn/**`) or the root Clojure build file are snapshotted so ordinary source refreshes never rerun resolution. Classpath JARs prefer a sibling `-sources.jar`; tools.deps resolves missing Maven `artifact$sources` classifiers through bounded Clojure CLI batches, retaining main-JAR fallback when a source artifact is unavailable. Extracted sources are checksum-cached below `CODE_LENS_HOME/dependencies/sources`, indexed through the ordinary tables, and identified by `DependencyArtifact`/`DependencyFile`; the legacy `MavenProject.rootPom` column stores the detected root build file. Query defaults to workspace scope while context falls back automatically. Preserve failure isolation: a build-tool failure must not replace an existing published index. `CODE_LENS_MAVEN=0` is the global kill switch for all three tools and Python virtualenvs, and automatic dependency execution is only safe for trusted repositories. Failed/disabled generations must retry when resolution is enabled. Maven uses a reactor-wide `test-classpath` union; Leiningen/tools.deps use `classpath` (`modulePath` is the repo root and `direct = -1`). Python virtualenvs execute nothing: `python_resolve_venv` reads each `site-packages/*.dist-info/RECORD`, indexes the listed `.py` files in place (no extraction cache; artifact `pypi:<name>:<version>`, scope `venv`, empty checksum, skipped by the cache-marker checks), never reuses a prior generation (re-reading RECORDs is cheap), and snapshots `pyvenv.cfg` plus every RECORD as inputs. Dependency source files of every kind ride the parallel parse pipeline after the workspace walk (`StreamWalker.extra_paths`), in the same order as the sequential path.
- The C parser uses tree-sitter-c. It extracts functions/prototypes, globals, typedefs, structs/unions/enums, fields, enumerators, macros, documentation comments, type/value references, calls, and typed member accesses. External symbols use `namespace = ''`, file-local `static` symbols use the file path, and fields use the canonical aggregate name; C `File.namespace` is empty so existing context SQL resolves global calls. Receiver resolution uses typedefs and declared variable/parameter/field types, not compiler attribution. Keep `tests/test_c_support.c` green when changing it.
- Java, C, and Python extractors compare node kinds and fields through the shared null-safe `tsh_*` helpers: per-grammar `*K_*`/`*F_*` enums plus name tables resolved once to numeric ids by `tsh_ids_init`, which fails the parser's `_new` if a name is missing from the grammar (catches typos and grammar-bump renames). Never compare with `strcmp(ts_node_type(...))` or `ts_node_child_by_field_name` in those sections, and never use one grammar's ids on another grammar's tree. Extractor lookups go through `ParseMap`/`ScopeIndex` (same section): no per-use linear scans over bindings/symbols/fields/aliases/types and no per-node `ts_node_parent` in whole-tree walks - each made large files quadratic (`sqlite3.c` took ~60s; ~1s now); such changes must keep the dump hash identical.
- The Python parser uses tree-sitter-python (parser plus its external scanner). Module names come from the file path: the chain of enclosing directories holding `__init__.py` (never above the repo root), else the repo-relative path minus a leading `src/`; an added/removed `__init__.py` forces a full rebuild (the registry entry's `forces_full_rebuild` hook, checked by `repo_diff_forces_full_rebuild`). `File.namespace` is the dotted module; module-level symbols use the module as `namespace` and class members use `module.Class`. `import a.b [as x]` becomes `Alias` rows and `from m import n` (relative imports resolved) becomes `Referred` rows. References resolve syntax-first through imports, `self`/`cls`, `super()`, local bases, constructor-assigned locals, annotations (type strings keep generic arguments: `pkg.Ctx[pkg.Deps]`), locals assigned from typed attributes/subscripts/slices, loop targets over annotated containers (`enumerate`/`zip`/`.items()` included), and `isinstance()` narrowing (if bodies, `assert`, exiting `if not isinstance` guards); locals and builtins are not references, and untyped receivers keep an empty target. Module names below a `site-packages`/`dist-packages` directory are rooted there. Cross-file typing: the extractor emits `CodeLensTypeFact`s (CLASS with type-parameter count, BASE, MEMBER with declared type or `~N`, module-level from-import EXPORT, and DEFER for every attribute reference whose receiver type crosses files) into the `TypeFact` table, and `type_link_run` re-evaluates every DEFER row against the whole table before each publish (full builds via `type_link_staging`, incremental refreshes inside their transaction), rewriting `RefData.targetNamespaceTerm` to the declaring class (following re-exports, bases with argument substitution, and container element types) or restoring the local fallback target. Its output must depend only on the final fact set (duplicate facts resolve by deterministic preference) so incremental refreshes stay equivalent to full rebuilds. Node kinds/fields compare as precomputed numeric ids, and expression walkers stop at `PY_MAX_DEPTH` to protect 512 KB worker stacks. Keep `tests/test_python_support.c` green when changing it.
- The database wrapper owns SQLite open modes (read-only for queries with a busy timeout and a progress-handler deadline, read-write only for staging builds), prepared statements, the pipe-format result renderer, and error reporting.
- Indexing builds each repo's database in a staging SQLite file and publishes it atomically as `CODE_LENS_HOME/repos/<repo-dir>/index.sqlite`. Indexing/auto-refresh and removal take the same blocking per-repository `fcntl` lock under `CODE_LENS_HOME/repos/.locks/`, so writers across MCP processes serialize and a waiter rechecks staleness after the active publisher finishes. Lock files persist deliberately (process exit releases lock ownership; unlinking could split contenders across inodes). The default **raw emitter** encodes `File`/`Symbol`/`Ref`/`Keyword`/`Alias`/`Term` rows directly into SQLite b-tree pages in memory, commits a tiny transaction (schema, `Repo` row, adopted sidecar FTS shadow tables), then grafts the table and secondary-index b-trees into the file after COMMIT (index payloads are pre-sorted on side threads; graft writes run on three threads). Any raw-path failure retries the whole build with the classic prepared-`INSERT` emitter (`CODE_LENS_EMITTER=classic` forces it); the `SymbolFts` FTS5 table is built concurrently on the sidecar thread either way.
- Indexing parallelizes file read/parse/extract by default, capped at 8 workers. Set `CODE_LENS_INDEX_THREADS=1` to force the sequential path, or set an explicit worker count for benchmarks.
- When the repo is a git checkout, clean tracked files are read from the git object store (mmap'd packs + inflate, `.git/index` stat contract) instead of per-file open/read/close; anything uncertain falls back to the working file, keeping output byte-identical to a filesystem build. `CODE_LENS_GIT_BLOBS=0` disables it; `git_blob_reads`/`git_file_reads` appear under `CODE_LENS_PROFILE=1`. Pack objects inflate through vendored libdeflate (whole-buffer, known output size) via a per-reader reused decompressor; loose objects stream through the system zlib (`-lz`) via a per-reader reused stream. Delta bases referenced by two or more chain links are pre-resolved at source init into an immutable shared cache that workers read lock-free and borrow from; per-thread reader caches memoize the rest, and cache hits are borrowed, not copied (only the final blob handed to the parser is owned).
- Explicit CLI commands and public APIs identify repositories by canonical path alone (no repo names): `--repo`/API paths expand `~/`, retain plain-directory support, and resolve any path inside an indexed repository to that repository. MCP `query`, `context`, and `sql` accept an absolute worktree root or any path inside it; `repo` is optional and defaults to the directory where the server was started, which is not necessarily the client's working directory.
- Search implements list/query/context/sql output over the SQLite index (`query` combines Symbol FTS matches with file-diverse Keyword prefix matches; keyword locations round-robin across matching files and report truncation, while a zero-row multi-term AND match is retried as OR with a leading notice line). MCP exposes exactly `query`, `context`, and `sql`; cache inventory, freshness, and removal remain CLI/public-API administration details. MCP reads transparently prepare current worktree data and return a generic availability error rather than stale data or maintenance notes. `query` supports `excludeTests`/`--exclude-tests`, `kind`/`--kind`, `path`/`--path`, `scope`/`--scope`, `dependency`/`--dependency`, and `limit`; workspace is the default scope, while context falls back to dependency definitions automatically; symbol kinds filter symbols only and suppress keyword rows, `kind` = `keyword` returns keyword rows only, and unknown kinds get a note naming the valid values. `list`, `query`, and `context` run a read-time staleness check that compares indexed file size/mtime snapshots with the current repo, detects new supported Clojure, Java, C, or Python files, and reports elapsed check time; direct API/CLI reads only warn. MCP `sql` remains read-only with respect to user SQL. `context` matches references on `Ref.symbolBase`, counts unqualified references only in files whose namespace defines the symbol or that refer it in (`Referred` rows from Clojure `:refer`/`:refer :all`/`:use`, Java static imports, and Python from-imports), and filters resolved references by `Ref.targetNamespace` against namespaces that define the symbol. Java extraction fills that target from imports/enclosing types/declared receiver types; C fills it from linkage and aggregate receiver types; Python fills it from imports and self/constructor/annotated receiver types. Context then lazily maps referenced files to render nearby source snippets from `Ref.startByte`/`Ref.endByte`; Clojure slash, Java/Python dot, Java hash, and C arrow qualifiers in user input are stripped when no exact dotted definition exists, and `excludeTests`/`--exclude-tests` drops test-path rows (and test-kind definitions) from all three sections. `fullSource`/`--full-source` renders exact definitions from their spans via `source(..., s.content)` (Class Dossier unaffected). Model-facing MCP metadata must not mention `index`, `stale`, or `cache` (mcp-smoke enforces this). Its `namespace`/`--namespace` and `path`/`--path` filters select definition candidates, so references are included only when they resolve to a selected candidate—not merely filtered by reference site.

## Repository conventions

- Keep development in ISO C23 with a pure-C toolchain end to end.
- Vendor source trees are local artifacts populated by `scripts/vendor-deps.sh`; pins live in `vendor/deps.lock` (git commit for clones, archive SHA-256 for the SQLite amalgamation), and vendored source trees should not be committed.
- Application SQL always binds parameters (`?1`-style); never interpolate user input into SQL text. The `sql` command passes user queries through on a read-only connection with an authorizer (reads only; ATTACH/PRAGMA/writes denied) and a 100-row output cap.
- SQLite compile defines live in the Makefile (`SQLITE_DEFINES`); FTS5 must stay enabled, and `SQLITE_THREADSAFE=2` requires that each connection is used by one thread at a time (the single-writer indexing funnel and per-operation read connections already satisfy this).
- Use an isolated `CODE_LENS_HOME` for smoke tests and profiling, for example `CODE_LENS_HOME=/tmp/code-lens-home ./build/code-lens index ...`, so test runs do not mutate the per-repo indexes under the default `~/.code-lens/repos/`.
- Arena allocations are lifetime-managed by arena marks/resets, not individual frees. Do not add no-op cleanup APIs for arena pointers; if removing cleanup noise exposes empty cleanup helpers, remove the helpers too while preserving real external cleanup such as `ts_parser_delete`, `sqlite3_finalize`, `sqlite3_close`, `munmap`, and `closedir`.

## SQLite and indexing performance

- When diagnosing `index` slowness, measure phases before naming a root cause. Useful signals are `CODE_LENS_PROFILE=1`, final `indexed ... files, symbols, references, keywords, aliases` counts, the staging/published `index.sqlite` size, and a CPU sample during the suspected phase.
- The live local benchmark fixture is a checkout of the `big-repo` Clojure monorepo. As of 2026-07-09 the full-repo counts were 2035 files, 18862 symbols, 453867 references, 245498 keywords, and 12997 aliases, indexing from scratch in ~0.27s warm. That repo drifts over time, so before comparing counts or timings re-baseline with the pre-change binary: run `scripts/benchmark-index.sh --path <big-repo-checkout>` without `--expect-*` flags (or a plain `index` run) to learn current counts, then hold those counts fixed across the change.
- To compare two binaries on a laptop, use `scripts/ab-bench.sh --a <old> --b <new> --path <fixture> --expect-* ...`: it interleaves single runs (ABAB) with cooldowns and reports per-binary wall and child-CPU medians plus two exact paired tests, the sign test and the more powerful Wilcoxon signed-rank test (wall is the decision metric; CPU is diagnostic - e.g. PGO measured 2.5% less CPU but 6.4% more wall because the layout hurt the critical-path emit thread, so it stays unused). Start a session with a null A/B (`--a X --b X`, 8 pairs) to learn the day's noise floor (~0.5% on a quiet machine, +/-10% under background load). Keep the pre-change binary at a scratch path and treat a >2% median regression as a revert signal; confirm keep/discard decisions with 16+ pairs, and re-verify a stack of sequentially accepted changes against the original baseline at the end - accepting each step's noisy best reading systematically overstates the cumulative win. `scripts/gate.sh --baseline <bin> --path <fixture>` runs the whole per-change battery (forced rebuild, `make test`, mcp-smoke, dump-hash equivalence, count-pinned ab-bench) in one command. For write-path equivalence checks, compare `sqlite3 index.sqlite .dump | grep -v 'INSERT INTO Repo' | shasum`: output is deterministic per machine except the Repo row's indexedAt timestamp. Unattended overnight benches can hit display-off App Nap throttling (one observed run stretched 0.4s to 152s wall at near-zero extra CPU); medians and the rank test absorb such outliers, but check the max column before trusting means.
- On the benchmark fixture the parallel pipeline's wall time is bound by the single-threaded emit path with the walker close behind: after the 2026-07 worker-offload series (reference target resolution, File stat capture, term hashes, FTS row and id-string pre-pack all moved to parse workers) emit busy is ~0.087s against a ~0.06-0.075s walker collect, and the pipeline ends on the emit tail. Emit-side savings only convert to wall while emit strictly gates; worker-side read/parse CPU reductions still show up directly in `CODE_LENS_INDEX_THREADS=1` runs and in the summed `read`/`parse_extract` phases under `CODE_LENS_PROFILE=1` (the offload series shifted ~20ms of parse-phase attribution from the emit phases; totals are what matter). A 4-thread ordered parallel walker was measured at +7.6% wall and discarded: 8 parse workers + emit + feeder already saturate a 10-core machine, and faster collection cannot shorten a pipeline whose emit thread is ~96% busy. The pre-pack work is skipped in sequential mode where it cannot pay. `CODE_LENS_PROFILE=1` also prints `term_intern_calls`/`term_intern_misses` (misses = Term row count) and `raw_leaf_closes` for judging emit-path changes by moved work rather than wall alone.
- The post-COMMIT tail was restructured in 2026-07 (full build ~0.21s -> ~0.17s, -17.5% cumulative at 16/16 pairs): on the raw path the FTS sidecar builds in a `:memory:` database (no sidecar file at all; the thread leaves its connection open and the main thread adopts through it after the join - sequential use of one connection keeps SQLITE_THREADSAFE=2 honest), the load transaction no longer waits for the sidecar or copies shadow tables (COMMIT dropped from ~6ms to ~0), and after the table graft the two big shadow tables (`SymbolFts_data`, `SymbolFts_docsize`) are grafted as raw pages encoded on the sidecar thread while tiny `_idx`/`_config` copy over SQL in a short post-COMMIT transaction. Failure ladder: shadow graft -> full SQL adopt -> post-COMMIT in-place FTS rebuild (Symbol is readable once the graft ran) -> classic retry. The classic path keeps the file-based sidecar and in-transaction copy. Raw grafts guard root overwrites with `RawGraft.root_set` - a tree index whose root was never captured must not be written, or live pages get zeroed.
- The staleness check is walk-bound, not stat-bound: the new-file walk is a full-tree readdir (~50ms on the fixture, same traversal as the pipeline's collect). The 2026-07 rework runs the indexed-file stats dirfd-batched (paths sorted, one `open` per directory, `fstatat` per name) on 8 striped threads, and the new-file walk on 4 workers claiming depth-2 subtrees with per-worker batched callback flushes (order is irrelevant for membership checks; `diff.added` is sorted afterwards so incremental re-parse order stays deterministic). Run the two phases sequentially: concurrent stat and walk passes were measured to fight over the same directory vnode locks and burn 5x the CPU for no wall win - the same kernel ceiling that sank the build-pipeline parallel walker. Net: check ~73ms -> ~50ms, at ~3x the CPU of the serial version.
- When building binaries from several commits in quick succession (A/B bisection), force the app object to rebuild (`rm build/release/obj/code_lens.o`) or `make clean`: the system GNU make 3.81 compares mtimes at whole-second granularity and can silently reuse a stale object after a fast `git checkout`. Verify with `cmp` that supposedly different builds actually differ.
- After write-path or schema changes, validate both counts and read behavior by reopening the index and running `list`, `query`, `context`, and `sql` smokes. Bump `CODE_LENS_INDEX_FORMAT_VERSION` (stamped as `PRAGMA user_version`) whenever the schema changes so old indexes report "re-index required" instead of being misread, and also when an extraction fix changes output that an incremental refresh would keep in unchanged files (a stamp mismatch forces a full rebuild).
- Build pragmas (`journal_mode=OFF`, `synchronous=OFF`, `temp_store=MEMORY`) are safe only because the staging file is published by atomic rename; do not reuse them on databases opened in place.
- Prepared statement bindings use `SQLITE_STATIC` only for arena-backed memory that outlives the step; stack-local buffers must bind with `SQLITE_TRANSIENT` (see `bind_text_copy_len`). Finalize all statements before closing their connection.
- FTS5 `SymbolFts` is an external-content table over `Symbol` built once per index build by the FTS sidecar thread (Symbol rows mirrored in rowid order into a sidecar database whose shadow tables are then adopted inside the load transaction); any sidecar failure or `CODE_LENS_FTS_SIDECAR=0` falls back to an in-place `INSERT INTO SymbolFts(SymbolFts) VALUES('rebuild')` under the classic emitter (the default raw emitter requires the sidecar and fails over to a classic retry). Its tokenizer splits on `- . / _` in addition to unicode61 defaults; user query terms are quoted, `*`-suffixed prefix phrases. Mid-word substring matching is intentionally not supported.
- The index format is `CODE_LENS_INDEX_FORMAT_VERSION` 18 (stamped as `PRAGMA user_version`; trust the `#define` in `src/code_lens.c` over any number written in docs; 17 added the `TypeFact` table and the Python type link pass; 18 added `Symbol.startByte`/`endByte` and `Referred.alias`): `File` carries index-time `size`, `mtimeSec`, and `mtimeNsec`, plus per-file contiguous range columns `refFirst`/`refCount`, `keywordFirst`/`keywordCount`, and `symbolFirst`/`symbolCount` (all known before a file's rows emit, from the running counters); the high-volume rows live in dictionary-encoded physical tables `RefData` and `KeywordData` whose text columns hold `Term` rowids (interned strings), plus `fileId` (the `File` rowid). Compatibility views `Ref` and `Keyword` reconstruct the text-shaped rows with the historical column names, so read queries are unchanged. `Ref` carries zero-based `startByte`/`endByte`, `symbolBase`, and `targetNamespace`. Clojure fills these as the text after the last `/` and the require-alias-resolved (or verbatim) qualifier; Java fills them as the final type/member and syntax-resolved fully qualified target type; C fills them as the final identifier plus file-local or aggregate target when known. Empty target text means global/unresolved/unqualified. All are computed on parse workers. `Keyword` carries the literal keyword, `keywordBase`, qualifier, and target namespace for `:`/`::` keyword usage rows. `Symbol.content` stays the short form (FTS-searched; elides some bodies) while `Symbol.startByte`/`endByte` span the whole definition (same node as `startLine`/`endLine`; both Clojure backends must agree, enforced by the differential test); full text is never stored and is read back by the `source(filePath, startByte, endByte [, fallback])` SQL function registered on read connections (indexed `File` paths only, size/mtime-checked, truncated past 256 KiB). `Referred.alias` is the local binding name (equal to `symbol` unless renamed, empty for `:all`).
- Re-indexing an already-indexed repo takes an incremental path by default: the read-time staleness diff yields changed/missing/added path sets, and when the diff is at most 20% of indexed files the published `index.sqlite` is cloned (APFS copy-on-write via `copyfile`, stream copy elsewhere), doomed files' rows are deleted with primary-key range deletes driven by the File range columns (O(diff), never a full-table scan), changed/added files are re-parsed and appended with classic prepared statements (Term dictionary preloaded, RefData/KeywordData ids continuing past the surviving maximum — readers treat ids as opaque, so holes are fine), `SymbolFts` is maintained per row ('delete' commands fed the old values before the row deletes, one catch-up insert after), and the clone is published by rename. An up-to-date repo skips the rebuild entirely and reports the stored totals. Any surprise falls back to the full rebuild; `CODE_LENS_INCREMENTAL=0` disables the path and `CODE_LENS_INCREMENTAL=force` skips the 20% budget (used by tests). Equivalence contract: an incremental refresh must be observably identical to a full rebuild for `query`/`context` and deterministically ordered SQL over the views — `tests/test_main.c` `test_incremental_reindex` enforces it, plus kill-switch and over-budget fallbacks (a full rebuild's RefData ids are gap-free; an incremental one has holes — that's the test's path marker). Measure with `scripts/bench-reindex.sh --path <repo>`: on the 2035-file fixture (2026-07-11) the no-op re-index is ~79ms and a one-file touch ~120ms wall / ~0.37s CPU vs ~0.17s / ~1.1s CPU for a full rebuild; both are now dominated by the staleness check itself.
- Parser and walker optimizations must preserve the benchmark fixture's exact counts: re-baseline with the pre-change binary, then hold the counts fixed across the change. Use length-checked source-slice comparisons for parser literals such as `:require`, `:as`, `ns`, and definition forms; do not use prefix-only `strncmp`. Symbol text extraction uses tree-sitter field access (`symbol_value_slice`), which strips metadata nested inside `sym_lit` nodes; definition-form detection compares the grammar's `name` field child (the base name after the namespace delimiter) so namespaced heads like `foo/defn` and metadata-annotated heads keep working.
- `Ref` ids are global ordinals assigned in emission order, so emission stays single-threaded and in file order.
- `CodeLensFileCallback` receives a path valid only for the duration of the callback. Internal collectors copy paths they need to keep; future callbacks should do the same instead of storing the provided pointer.
